# 需求拆解表（第 5 週：需求拆解四步驟）

專題名稱：**勤益社團一站通**（社團瀏覽＋線上報名＋本地 AI 小幫手）

## ① 目標是什麼
- 商業情境：校內社團博覽會前後，新生想快速比較社團，社團幹部想收到完整的報名資料。
- 具體目標：新生用手機瀏覽社團、選好社團並送出報名；幹部收到姓名、學號、Email、社團後可以確認。
- 驗收問題：新生能不能在 3 分鐘內完成報名？資料不完整時是否被即時提醒？
- 兩種狀態要分開：
  - 「已收到報名申請，待社團幹部確認」（資料已送出）
  - 「已登記候補」（社團額滿時）

## ② 有哪些畫面或功能
| 畫面 | 使用者看到什麼 | 使用者能做什麼 |
|---|---|---|
| 社團一覽 | 社團卡片（名稱、類別、時間、地點、社費、名額、標籤） | 關鍵字搜尋、類別篩選、只看有名額、按「我要報名」 |
| 活動日程 | 三個活動（日期、時間、地點、說明） | 閱讀 |
| 線上報名 | 表單（姓名、學號、Email、社團、同意個資） | 即時驗證、送出、看到結果、重新報名 |
| AI 小幫手 | 對話區、連線設定、System Prompt | 取得模型清單、選模型、問問題、快速提問 |
| 專題說明 | 期中項目對應表 | 閱讀 |

## ③ 資料從哪裡來
| 資料 | 來源 | 備註 |
|---|---|---|
| 社團、活動 | 固定內容：`data/clubs.js`（模擬資料） | 正式使用時由社團／學生會維護 |
| 報名資料 | 使用者輸入 | 本專題無後端，不儲存 |
| AI 回答 | 本機 LM Studio 模型 | 只能依 System Prompt 內的社團資料回答 |
| 即時名額 | 無 | 名額為靜態示意，AI 不得宣稱查到即時名額 |

## ④ 限制條件
- 手機優先（社群連入為主），768px 以下單欄顯示。
- Email 格式必須即時提示；學號 8～10 碼英數字。
- 本地 AI：只在自己電腦執行，不傳雲端；回覆需繁體中文；資料不足時回答「目前資料不足，請聯絡社團」。
- 無後端、無資料庫，可直接放 GitHub Pages。
- 無障礙：`label` 對應欄位、`aria-invalid`、`role="status"`、鍵盤可操作。

## 同學互查：還有哪些地方在猜？
- 「剩餘名額」報名成功後要不要扣？→ 本版不扣（無後端），結果頁明講「待幹部確認」。
- 同一個學號重複報名怎麼辦？→ 本版不處理，列為後續改進。
- 網路中斷或 AI 沒開時會出現什麼？→ 顯示可能原因與保留問題，可重試。
