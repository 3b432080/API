# AI 協作紀錄（Prompt 與迭代追問）

> ⚠️ 繳交前請把「你實際與 AI 對話」的完整文字或截圖貼進來。
> 下面是依照課堂「需求拆解四步驟＋架構 Prompt」格式整理的版本，請依你真實的對話修改，
> 不要原封不動繳交。

## 第 1 輪：架構 Prompt（商業需求部分）
```
我想規劃一個校園社團報名網站，主要供手機操作。
新生查看社團、用關鍵字與類別篩選，填寫報名表後送出申請；社團幹部確認後報名才成立。

四個畫面：社團一覽、活動日程、線上報名、AI 小幫手。
社團資料：編號、名稱、類別、時間、地點、社費、名額、介紹、標籤。
報名資料：姓名、學號、Email、社團、是否同意個資使用。

限制：無後端，可放 GitHub Pages；768px 以下單欄；
AI 小幫手要連到我電腦上的 LM Studio（http://127.0.0.1:1234/v1/chat/completions）。
```

## 第 1 輪：交付內容部分
```
請先提供：① 頁面與檔案結構 ② 各檔案用途 ③ 共用內容與元件 ④ 使用者操作流程與資料流向
⑤ 正式使用時還需要的儲存與管理功能。
先規劃架構，不要寫完整程式碼。不確定的需求請列出待確認問題。
```

AI 回應重點（摘要）：index.html、assets/css/style.css、assets/js/app.js、assets/js/components.js、data/clubs.js；
元件：ClubCard、EventItem、ChatBubble。

## 第 2 輪：具體追問（迭代案例）
- 我發現的落差：第一版報名表只有「選社團」，沒有處理「名額已滿」的情況。
- 追問：
```
有些社團名額是 0。請讓卡片顯示「名額已滿（可候補）」，按鈕改成「登記候補」，
送出後的結果文字要和一般報名不同。請列出要調整的資料欄位與檔案。
```
- 修正版檢查：名額 0 的街舞社 → 結果顯示「已登記候補，有名額時由社團通知」。

## 第 3 輪：驗證與表單
```
請在 Email 欄位加上即時驗證：格式不對時在欄位下方顯示紅字，格式正確時顯示綠字提示。
學號限制 8～10 碼英數字。未碰過的欄位不要先顯示錯誤。
```

## 第 4 輪：串接本地 AI（對照第 6 週完整 Prompt）
```
請在網頁中串接 LM Studio：POST 到 http://127.0.0.1:1234/v1/chat/completions，
送 model、messages、stream:false、max_tokens:512、temperature:0.2。
以 choices[0].message.content 取得回答並用 textContent 顯示。
要有送出中狀態、停用按鈕、120 秒逾時、HTTP 錯誤處理。
user 訊息要附上店家資料並逐項回答；資料不足要明說；失敗要保留問題並可重試，不可編造。
```
System Prompt 全文可在網頁「AI 小幫手 → 查看送給 AI 的 System Prompt」看到。

## 第 5 輪：元件化（第 8 週）
```
請把頁面中重複出現的區塊拆成 Vue 元件，並用 props 傳入模擬資料：
社團卡片（ClubCard）、活動項目（EventItem）、對話泡泡（ChatBubble）、欄位提示（FieldMessage）。
用 v-for 搭配 data/clubs.js 的模擬資料組裝畫面。
```

## 修改理由與檢查方法
| 修改 | 理由 | 如何檢查 |
|---|---|---|
| 加入候補狀態 | 第一版沒有符合「名額為 0」的商業規則 | 選街舞社送出，看結果文字 |
| 欄位 blur 後才顯示錯誤 | 避免使用者還沒輸入就被紅字打擾 | 進入頁面時欄位無錯誤訊息 |
| System Prompt 加「不得宣稱即時名額」 | 資料是靜態的，AI 不能假裝查得到 | 問「現在還剩幾個名額」，應引導到報名表 |
| AI 失敗保留問題 | 本地模型可能逾時或沒開 | 關掉 LM Studio Server 後送出，問題仍在輸入框 |
